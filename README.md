# 薄板工厂双班抽检复盘台账

材料质控组使用班次领用清册、整数微米测读、各班交班清单和实物领取记录，复算当时抽检安排的条件漏检率。结果供分析员安排轧制工序复核，次班按正式报告号领取。

## 日常流程

1. 班长核对各班领用清册及共同留样架的具名共享登记。同名私件分别归属各班，同一个共享登记可在不同站库解析为同一共享键。
2. 班长录入测读或勘误。有效整批产生新的确切修订，未更改的测读随版沿用，旧修订仍可查询。
3. 班长选定本站规程版本及测读修订，把实际抽检框和逐层配额冻结到方案号。读数达到该版上限即为异常。
4. 班长按固定方案号发行班件。班件保留共享实物键及本站异常标记，以及每层的配额和私件分类计数。私件逐片编号和测读留在站库。
5. 收件员核验发行号、规范正文和 SHA-256 校验值，实收入账。同号同件重投取得原实收号，同号异件被拒绝。
6. 站库关闭后，分析员从领取记录抄录去重实物数 `m`，选定两份不同班次的实收件进行核算。
7. 中心把条件质量、条件漏检率或不可达结论、两份父件及回执一起签存。实物数不可达时，分析员回查领取记录和所选方案。
8. 次班凭报告号领取原定稿、父件出处及回执，再继续工艺复核。以后勘误、重开或签发新报告，原号仍返回同一定稿。

## 公开接口

使用 Python 3.11 标准库。`ledger.open_station(path)` 与 `ledger.open_center(path)` 分别打开并初始化站库与中心库。调用方关闭连接。`init_station(db)` 和 `init_center(db)` 可重复执行，保留已存业务记录。业务入口管理自己的事务。`samples.demo.load_sample` 在一个站库事务内装载固定样例，重复装载同一 `sample_key` 时返回原发行及原字节，原修订和后续勘误均保留。

| 模块 | 调用及结果 |
| --- | --- |
| `register.revisions` | `revise(db, shift_id, changes) -> revision_id`。`changes` 是站内编号到 `(共享登记名称或 None, 整数微米读数)` 的非空映射。勘误沿用该编号已绑定的归属。`load_revision(db, revision_id)` 读取历史快照。 |
| `sampling.protocols` | `register_protocol(db, shift_id, version, threshold)` 登记本站规程，重复登记同口径返回原版本。修改口径使用新版本。`load_protocol(db, shift_id, version)` 读取指定版本。 |
| `sampling.design` | `freeze(db, shift_id, revision_id, protocol_version, layers, quotas) -> design_id`。`layers` 将层名映射到站内编号序列，`quotas` 将每个层名映射到精确整数配额。`load_design(db, design_id)` 读取完整冻结框。 |
| `exchange.issue` | `issue(db, design_id) -> (issue_id, wire_bytes)`。每次发行均有独立发行号。 |
| `exchange.intake` | `receive(db, issue_id, wire_bytes) -> receipt_id`。`exchange.catalog.load_receipt(db, receipt_id)` 可查规范字节、已解码证据及校验值，未知号返回 `None`。 |
| `analysis.risk` | `publish(db, left_receipt_id, right_receipt_id, m) -> PublishedReport`。`record` 持有正式号和精确 `Fraction` 结果，`parents` 按请求顺序列出实收号、发行号、方案、修订、规程和校验值，`receipt` 持有报告号和回执号。 |
| `report.retrieve` | `read(db, report_id) -> PublishedReport | None`。未知报告返回 `None`，读取通过固定实收号还原父件。 |

班次、层名、版本及登记名称使用非空文本。共享登记名称是同一工厂登记簿中经确认的键；不同班的本地编号可以不同。先提交测读再冻结，未选进框的测读留在修订内。一个实物在一个框中最多出现一次，重复别名也算重复。配额必须覆盖全部层并在零到层大小之间，空层取零。无放回选择的可能数和质量使用精确整数及有理数。布尔值不会被当作测读、配额、标识号或 `m` 的整数。异常输入抛出 `ledger.InvalidInput`，未知的请求来源或冻结依据抛出 `ledger.UnknownRecord`。SQLite 写入失败原样抛出，成功签报仅在事务提交后返回。坏件、错件、非法请求和回执持久化失败均保留此前记录。

班件 V1 是规范 UTF-8 JSON 字节，外层含 `payload` 和 `sha256`。校验值覆盖规范正文。正文含 V1 版本、发行号、班次、方案和修订号、规程版本及分层证据。证据按层名和共享键排序，朱验时检查字段、整数、布尔标记、共享键唯一性和配额范围。两班独立站库通过相同的已确认登记名得到同一个共享键。报告保留请求顺序。

## 计算口径

每个层从大小 `n` 的框内等概率无放回取 `q` 片。枚举实际选中的共享键子集后，用组合数折算还须选中的私件。整层总抽法数为 `C(n,q)`。若该子集含异常，则其零异常质量为零，否则零异常抽法数为在该层正常私件中完成剩余配额的组合数。以原抽法数计权，各层及两班事前独立。每对抽法的去重实物数等于总配额减去实际入样共享键的交集大小。共享实物的两个本站标记各自生效。`condition_mass` 是去重数等于 `m` 的质量，零异常条件概率是同一条件下的零异常联合质量除以条件质量。可达时可能报 `0/1`，不可达时状态为 `unreachable` 且概率为空。过程不使用随机模拟，适用于有限复盘框。

## 核验与演示

在物化后的项目根目录执行控制台提供的完整核验入口。

```sh
python3 -B check_project.py
python3 -B -m samples.demo
```

演示在独立临时目录使用两份站库和一份中心库。样例中甲从 x、a 各等概率抽一片，乙从 x、b 各等概率抽一片，只有共享 x 报异常。`m=1` 的条件质量为 `1/4`，零异常概率为 `0/1`。`m=2` 的对应值为 `3/4`、`1/3`。`m=3` 不可达。演示打印重开中心后按号读回的结果、原父件和回执。回归还核对同边际不相交输入、四片不等权输入、层独立性、零配额、班内判级、断源实收、拒绝、回滚和历史领取。
